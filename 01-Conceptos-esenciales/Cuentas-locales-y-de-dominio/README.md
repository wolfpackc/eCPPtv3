# Cuentas locales, cuentas de dominio y cuentas de equipo

Un ordenador Windows normal puede tener cuentas locales como `PC01\Edu`, `PC01\Pepe` o `PC01\Maria`. Estas cuentas existen en la base local del propio equipo y su identidad se basa en el **SID local del PC + un RID distinto para cada cuenta**. Si después `PC01` se une al dominio `miempresa.local`, esas cuentas locales **no desaparecen, no se convierten y no se copian automáticamente a Active Directory**: siguen siendo cuentas válidas únicamente como identidades locales de ese ordenador.

Al unir `PC01` al dominio, Active Directory crea o utiliza una **cuenta de equipo** como `PC01$`. Esta cuenta existe en Active Directory, tiene un SID basado en el **SID del dominio + su RID**, y representa al propio ordenador frente al dominio. `PC01$` no es una cuenta pensada para que una persona inicie sesión de forma interactiva; la utiliza el equipo para autenticarse ante el dominio, mantener el *secure channel* con el controlador de dominio, aplicar GPO y acceder a servicios o recursos utilizando su identidad de máquina.

Las **cuentas de dominio de usuarios** se crean aparte en Active Directory, por ejemplo `MIEMPRESA\Edu` o `edu@miempresa.local`. No son las mismas cuentas que `PC01\Edu`, aunque tengan el mismo nombre, y **no quedan atadas a un único ordenador**: pueden utilizarse para iniciar sesión en otros equipos unidos al dominio siempre que las políticas y permisos lo permitan. La cuenta como identidad se administra en Active Directory, no en la base local de usuarios del host; al iniciar sesión, Windows sí puede crear un perfil local para ese usuario y almacenar información de inicio de sesión en caché, pero eso no convierte la cuenta de dominio en una cuenta local.

La diferencia práctica aparece al acceder a recursos corporativos. Si `MIEMPRESA\Edu` tiene permiso sobre `\\SERVIDOR\IT`, al iniciar sesión con esa cuenta Windows puede usar sus credenciales de dominio —normalmente mediante Kerberos o NTLM— y acceder al recurso sin volver a pedir usuario y contraseña cuando el servicio admite autenticación integrada. Si, en cambio, se inicia sesión como `PC01\Edu`, el ordenador sigue estando unido al dominio, pero la sesión corresponde a una identidad local; esa cuenta no recibe automáticamente los permisos de `MIEMPRESA\Edu` y, para acceder al mismo recurso SMB, normalmente tendrá que proporcionar aparte unas credenciales válidas del dominio.

Una cuenta de dominio tampoco es automáticamente administradora. Si `MIEMPRESA\Edu` pertenece a grupos o recibe permisos que le hacen administrador local de un equipo, entonces podrá realizar tareas locales como crear usuarios, instalar software o cambiar configuraciones en ese host. Esos privilegios dependen de los grupos, ACL y políticas que Active Directory o el propio equipo tengan configurados, no del simple hecho de que la cuenta sea de dominio.
